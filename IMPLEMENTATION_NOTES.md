# Implementation Notes
(For interview preparation — explains every technical decision in this app)

## Environment setup (Step 1)
- This dev machine has RVM (Ruby 2.6.5) and rbenv (Ruby 3.3.6) both installed. RVM's shell
  init exports `GEM_HOME`/`GEM_PATH` pointing at the RVM Ruby even in shells where rbenv's
  shims are first on `PATH` — RubyGems honors those env vars over what the active `ruby`
  would compute, so `rails`/`bundle`/`gem` silently resolved gems from the wrong install
  (surfaced as `Could not find 'racc'` errors). Fix used: `unset GEM_HOME GEM_PATH` before
  Ruby-related commands, rather than editing `~/.bash_profile`'s RVM sourcing, since that
  file is shared with other, unrelated RVM-based projects on this machine.
- Local Postgres requires a password for any TCP connection, but has passwordless **peer
  auth** on the unix socket for the OS user's own role (which is a superuser here, so it can
  `CREATEDB`). `config/database.yml` is therefore env-var driven: unset `DB_HOST`/`DB_PORT`/
  `DB_USERNAME`/`DB_PASSWORD` → connects over the socket with zero config (local dev);
  Docker Compose's Postgres sets all four to force a TCP connection to the container instead.
  One file, no manual comment-toggling between "local" and "Docker" blocks.
- Removed `solid_cache`/`solid_queue`/`kamal`/`thruster`/`brakeman`/`rubocop-rails-omakase`
  from the Rails-8-default Gemfile in favor of Redis + Sidekiq for cache and jobs, and
  because Kamal deployment isn't part of this project's scope. Kept `propshaft` even though
  it wasn't in the original gem list — Rails 8 needs an asset-pipeline gem to serve
  Tailwind's compiled CSS, and the auth generator's views already use Tailwind classes.
- Switched the test framework from Minitest to RSpec (`config.generators.test_framework =
  :rspec, fixtures: false` in `application.rb`) and deleted the generated `test/` directory
  and CI's Minitest/Brakeman/Rubocop jobs accordingly — those gems are no longer bundled.
- `spec/rails_helper.rb`: the RSpec generator defaults `config.use_transactional_fixtures =
  true`, which double-wraps each example in a transaction on top of DatabaseCleaner's own
  `:transaction` strategy. Set to `false` so DatabaseCleaner is the single source of truth.
- `config.active_job.queue_adapter = :sidekiq` is set app-wide in `application.rb`, then
  overridden to `:test` in `config/environments/test.rb` — specs run jobs inline rather than
  actually enqueuing to Redis.

## Authentication
- Using Rails 8 built-in auth generator with has_secure_password
- Chose this over Devise to keep dependencies minimal and show understanding of Rails auth internals
- Rails 8 uses `email_address` field (not `email`) and a separate `sessions` table
- Signup (`RegistrationsController`) isn't generated by `rails generate authentication` —
  added manually, reusing the same `start_new_session_for` helper the login flow uses so a
  successful signup logs the user in immediately.
- `Sidekiq::Web` is mounted at `/sidekiq` with no auth guard yet — fine for local dev, but
  needs a `Rack::Auth::Basic` (or admin-role) gate before this is ever deployed anywhere
  reachable.

## Concurrency Strategy (to be detailed in Step 3)
- Pessimistic locking at application level: Seat.lock.find(id)
- Unique partial index at database level on holds(seat_id) WHERE status = 'active'
- Together these prevent any two users from holding the same seat simultaneously

## Idempotency Strategy (to be detailed in Step 3)
- Booking confirmation uses find_or_create_by!(hold_id: hold.id)
- hold_id is unique on bookings table
- Repeated confirmation attempts return the existing booking, never create duplicates

## Caching Strategy (to be detailed in Step 4)
- Rails.cache backed by Redis (DB 1, separate from Sidekiq on DB 0)
- Cache key: "trips/#{from_city}/#{to_city}/#{date}"
- Cache invalidated on: seat hold created, booking confirmed, booking cancelled, hold expired

## Background Jobs (to be detailed in Step 4)
- HoldExpiryJob scheduled via Sidekiq perform_in(5.minutes, hold_id)
- On expiry: hold status → expired, seat status → available, cache invalidated
- If user tries to confirm after expiry: redirected to seat selection with error message
